01总体架构概览

本地单机进程架构：一个后台守护进程承载存储、队列、注册表与调度；CLI（未来 WebUI）作为客户端通过回环 HTTP 管理模型与任务。

1.2 两条核心数据流

任务链路（Phase 2 打通）

agent run → POST /v1/tasks
→ TaskService.submit（落库 + 入队）
→ Router（分类 / 能力 / 成本）
→ Planner（单任务直通）
→ Scheduler（并发 ≤ 2）
→ Worker（Workspace 分配）
→ AgentAdapter.invoke
→ Runtime 调用用户添加的模型
→ 事件流 → usage_records
→ Validator（build / test / lint）
→ 结果回写 tasks

模型管理链路（Phase 2 先行）

agent model add qwen3 ...
→ POST /v1/models
→ 校验（连接 / 计费 / 能力）
→ 落库 models
→ 审计 model_change_log
→ agent model list / update / remove / disable

初始注册表为空（ADR-0016）
运行时操作，无需重启 daemon（ADR-0017）

03数据模型与 SQLite Schema

7 张表：tasks / agent_runtimes / models / model_change_log / worker_runs / usage_records / metric_events。模型注册表初始为空，全部写入集中在 daemon 进程。

-- WAL 模式，单写者模型
PRAGMA journal_mode = WAL;

CREATE TABLE tasks (
  id             TEXT PRIMARY KEY,
  parent_id      TEXT,
  dag_group      TEXT,
  type           TEXT NOT NULL,
  prompt         TEXT NOT NULL,
  status         TEXT NOT NULL,
  agent_id       TEXT,
  model_id       TEXT,
  workspace_id   TEXT,
  priority       INTEGER NOT NULL DEFAULT 0,
  retry_count    INTEGER NOT NULL DEFAULT 0,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL,
  started_at     INTEGER,
  finished_at    INTEGER,
  result_summary TEXT
);
CREATE INDEX idx_tasks_status ON tasks(status);

CREATE TABLE models (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  provider     TEXT NOT NULL,
  model_id     TEXT NOT NULL,
  wire_api     TEXT NOT NULL,
  base_url     TEXT NOT NULL,
  auth_ref     TEXT,
  billing      TEXT NOT NULL,      -- json
  capabilities TEXT NOT NULL,      -- json
  status       TEXT NOT NULL DEFAULT 'active',
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  added_by     TEXT
);
CREATE UNIQUE INDEX idx_models_provider_model ON models(provider, model_id);

CREATE TABLE model_change_log (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  model_id   TEXT NOT NULL,
  action     TEXT NOT NULL,
  payload    TEXT,
  actor      TEXT,
  created_at INTEGER NOT NULL
);

CREATE TABLE usage_records (
  id                 TEXT PRIMARY KEY,
  run_id             TEXT NOT NULL,
  provider           TEXT,
  model              TEXT,
  input_tokens       INTEGER DEFAULT 0,
  output_tokens      INTEGER DEFAULT 0,
  cache_read_tokens  INTEGER DEFAULT 0,
  cache_write_tokens INTEGER DEFAULT 0,
  reasoning_tokens   INTEGER DEFAULT 0,
  latency_ms         INTEGER,
  cost_usd           REAL,
  source             TEXT NOT NULL DEFAULT 'provider'
);

04任务状态机与错误处理

created→ queued→ running→ succeeded
running→ failed→ retrying→ queued
running→ timed_out→ escalation→ queued
running→ cancelled   running→ validation_failed→ retry | escalate | ask_user
错误类别触发默认处理
auth_error401 / key 失效不重试 · 标记 error · 提示用户
agent_timeout超过程序级超时retry → escalate
agent_crash进程异常退出retry → escalate
agent_cli_failure非零退出且无结构化结果retry → ask_user
model_errorAPI 错误 / rate limitretry（退避）→ escalate
validation_failureValidator 判定失败retry → ask_user
workspace_conflictgit / 文件冲突ask_user

11风险与开放问题

风险 / 问题影响缓解
MIMO token-plan key 失效（实测 401）Claude+MIMO 链路不可用注册表用户管理 · 探测标记 error · 提示刷新
Claude 对 3P 模型成本估算失真（25K tokens 报 $0.127）预算误判成本以 provider usage × price 为准（ADR-0014）
ACP 生态未成熟适配器工作量不确定手写最小 NDJSON client + 集成测试兜底
daemon 崩溃导致任务悬挂状态不一致启动恢复：running → interrupted
并发写 SQLite锁竞争单写者模型 + WAL
WebUI 技术栈未定Phase 11 范围复用 /v1 API，前端可随时替换
